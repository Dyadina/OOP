# Фітнес-система управління планами 🏋️

Об'єктно-орієнтований прототип системи управління фітнес-планами на мові Java. Проєкт демонструє застосування основних концепцій OOP: наслідування, інкапсуляція, поліморфізм та залежності між класами.

## 📋 Опис проєкту

Система управління фітнес-планами включає:
- **Тренери** — створюють та коригують плани тренувань
- **Клієнти** — переглядають плани, відмічають виконання, оцінюють самопочуття
- **Носимі пристрої** — передають дані про здоров'я (пульс, сон)
- **Plани тренувань** — місячні плани з регульюванням навантаження при травмах

## 🏗️ Архітектура проєкту

### Структура файлів

```
OOP/
├── src/                          # Вихідний код
│   ├── Main.java                 # Головна програма з демонстраційним сценарієм
│   ├── FitnessApp.java           # Главна програма для управління системою
│   ├── User.java                 # Абстрактний базовий клас користувачів
│   ├── Trainer.java              # Клас тренера (наслідування від User)
│   ├── Client.java               # Клас клієнта (наслідування від User)
│   ├── DataProvider.java         # Інтерфейс для пристроїв
│   ├── WearableDevice.java       # Клас носимого пристрою (реалізація DataProvider)
│   ├── MonthlyPlan.java          # Клас місячного плану тренувань
│   ├── WorkoutSession.java       # Клас однієї тренувальної сесії
│   ├── HealthData.java           # Клас для даних про здоров'я
│   └── InjuryReport.java         # Клас для звітів про травми
├── bin/                          # Скомпільовані классы (.class файли)
├── Makefile                      # Автоматизація компіляції та запуску
├── .gitignore                    # Ігнорування .class файлів у Git
└── README.md                     # Цей файл

```

### UML-діаграма класів

**Наслідування:**
- `User` ← `Trainer`
- `User` ← `Client`

**Реалізація інтерфейсу:**
- `DataProvider` ← `WearableDevice`

**Агрегація/Композиція:**
- `FitnessApp` містить `Client` і `WearableDevice`
- `MonthlyPlan` містить `WorkoutSession`

**Залежності:**
- `Trainer` залежить від `MonthlyPlan`, `InjuryReport`, `WorkoutSession`
- `Client` залежить від `MonthlyPlan`, `InjuryReport`, `WorkoutSession`
- `FitnessApp` залежить від `DataProvider`

## 🔑 Ключові концепції OOP

1. **Абстракція** — клас `User` визначає загальну поведінку користувачів
2. **Наслідування** — `Trainer` та `Client` наслідують властивості від `User`
3. **Інкапсуляція** — приватні властивості класів (id, name, age, тощо)
4. **Поліморфізм** — метод `fetchHealthData()` реалізується в `WearableDevice`
5. **Фінальні методи** — `adjustLoad()` не може бути перевизначен в `Trainer`
6. **Інтерфейси** — `DataProvider` визначає контракт для пристроїв

## 🚀 Компіляція та запуск

### Перший спосіб (з використанням Makefile)

```bash
# Компіляція проєкту
make compile

# Запуск програми
make run

# Очистка скомпільованих файлів
make clean

# Перекомпіляція (очистка + компіляція)
make rebuild

# Відображення інформації про проєкт
make info

# Показати всі доступні команди
make help
```

### Другий спосіб (ручна компіляція)

```bash
# Компіляція всіх файлів
javac -d bin -sourcepath src src/*.java

# Запуск програми
cd bin
java Main

# Повернення в кореневий каталог
cd ..
```

## 🎯 Демонстраційний сценарій

Програма демонструє наступний випадок використання:

1. **Реєстрація користувачів** — додавання тренера та двох клієнтів
2. **Підключення пристроїв** — додавання двох носимих пристроїв
3. **Імпорт здоров'я** — отримання даних про здоров'я від пристроїв
4. **Створення плану** — тренер формує місячний план для клієнта
5. **Перегляд плану** — клієнт переглядає розроблений план
6. **Виконання тренувань** — клієнт відмічає тренування та оцінює самопочуття
7. **Звіт про травму** — клієнт повідомляє про травму
8. **Аналіз травми** — тренер аналізує травму та коригує навантаження
9. **Корегування плану** — система автоматично зменшує навантаження на 25%
10. **Завершення** — перегляд фінального стану та статусу системи

## 📊 Вхідні/Вихідні дані

**Вхідні дані:** Моделювання дій користувачів (реєстрація, створення плану, виконання тренувань)

**Вихідні дані:** Консольні повідомлення про:
- Реєстрацію користувачів
- Підключення пристроїв
- Дані здоров'я
- Створення та модифікацію планів
- Виконання тренувань
- Обробку травм
- Статус системи

## ✨ Особливості реалізації

- **Мінімальна складність** — простий прототип без складних логік
- **Консольний інтерфейс** — всі операції виводяться в консоль
- **Без зовнішніх залежностей** — використовується тільки стандартна Java-бібліотека
- **Без баз даних** — всі дані зберігаються в пам'яті
- **Укранські коментарі** — усі коментарі та висновки на українській мові
- **Англійські імена** — всі назви класів, методів, змінних на англійській мові
